# AtmosFlow Engineering Audit — September 2026

**Scope:** `atmosiq-v6/` (the canonical AtmosFlow codebase) at commit `b792eda` on `main`.
**Method:** every local quality gate was executed (install, full test suite with coverage, typecheck, lint, production build, `npm audit`, the `prod-ready` acceptance gate); five parallel static reviews covered the API layer, the database and sync layer, the assessment engine and standards corpus, the React/PWA frontend, and delivery/process. Every finding rated Critical or High in this document was re-verified by reading the cited lines, and the engine input-handling defect was reproduced by executing the engine.
**Severity scale:** Critical = exploitable or reaches a client deliverable with a wrong number; High = changes a conclusion, loses data, or blocks a deploy path; Medium = correctness or maintainability defect with a bounded blast radius; Low = hygiene.

## 2. Executive summary — the ten things to fix first

1. **Any signed-in user can grant themselves credits** (`api/credits.js:37-46`). The handler checks `!amount`, so `amount: -1000` passes, `current < -1000` is false, and the balance grows. Verified. *Fix: `Number.isInteger(amount) && amount > 0`, and debit atomically in SQL.*
2. **Any user can set their own plan, credits and beta flags with the anon key** (`supabase/schema.sql:32`). The profiles UPDATE policy is `using (auth.uid() = id)` with no column restriction, and no migration revokes column-level UPDATE. The client itself writes `plan` and `credits_remaining` from the browser (`src/utils/supabaseStorage.js:169-170`). Server entitlement reads those columns. Verified. *Fix: one `REVOKE UPDATE (plan, credits_remaining, …) ON profiles FROM authenticated, anon`.*
3. **Peer review can stamp another user's report "reviewed"** (`api/peer-review.ts:264-272`, `api/peer-review-respond.ts:248-256`). Both `assessments` updates run on the service-role client keyed only by the caller-supplied `report_id`, with no `user_id` filter; ids are client-minted `rpt-<timestamp>` strings. This is the exact liability boundary the report lifecycle exists to protect. Verified. *Fix: add `.eq('user_id', …)` to both updates.*
4. **`/api/checkout` is unauthenticated with an open redirect** (`api/checkout.js:58-97`). No JWT check; `userId` and `returnUrl` come from the body and flow into Stripe `success_url` and webhook metadata. Verified. *Fix: require the Bearer JWT; allow-list the return origin.*
5. **Three AI endpoints have no working rate limit** because their ledger inserts violate a CHECK constraint. Migration 012 allows only `('narrative','field_assistant')`; `inline-ai.js:330`, `inline-complete.js:288` and `pre-review-semantic.js` insert `'inline_ai'`, `'inline_complete'`, `'pre_review_semantic'`. supabase-js resolves with `{error}` rather than throwing, and the error is not read, so zero rows land and the daily caps never fire. Verified against the migrations. *Fix: widen the CHECK; read `error` on every ledger insert.*
6. **Offline work can be silently discarded** (`src/utils/supabaseStorage.js:619-630`). `saveAssessment` never throws on cloud failure (it re-queues internally), so `processSyncQueue` finishes with `remaining = []`, overwrites the queue with an empty array, and records `lastSuccess`. Verified. *Fix: make `saveAssessment` return a failure result and keep the item in `remaining`.*
7. **Non-numeric readings score as "within the reference range."** Reproduced by executing `scoreZone`: CO₂ entered as `"1,180"`, `"<5"` or `"abc"` produces a **pass** finding; `"1180"` produces **high**. PM `"<5"` and CO `"abc"` produce no finding at all, so the zone reads clean. `src/report/reportModel.js:52-55` strips non-numerics for the Results table, so the table and the engine disagree on the same cell. *Fix: one numeric parser in `scoring.js` that routes non-finite input to a data gap, never to pass.*
8. **The 30–60% RH band is still cited to ASHRAE 55 on every building profile** (`src/engines/buildingProfiles.js:36,80,125,150,173,198,222,258,287`) and in the DOCX narrative (`src/report/narrativeLibrary.js:59`), and to ASHRAE 62.1 on the Logger card (`src/utils/sensorThresholds.js:94`). ASHRAE 55-2023 sets only an upper humidity-ratio limit (0.012 kg/kg) and no lower limit; the 30–60% band is EPA moisture-control guidance. CLAUDE.md documents this exact fix as done; the humidity-citation sweep test omits these three files. Verified. *Fix: `label: STD.t.rh.ref`; add the files to the sweep.*
9. **Nothing gates a deploy.** The only workflows are the DB migration runner and RegLens CI. No `pull_request` job runs AtmosFlow's tests, typecheck, lint, build or acceptance gates; Vercel runs `vite build` only. The CHANGELOG records the consequence: 24 broken imports took every affected API route to 500 "since it was deployed", and the email cron failed all 96 runs in a week before a user noticed. *Fix: a 40-line `atmosflow-ci.yml` plus branch protection.*
10. **Server-side Sentry is never initialised in production.** `initSentryServer()` is called only from `server/index.js` (the container path), which cannot boot because the Dockerfile copies `api/` and `server/` but not `lib/` (`Dockerfile:31-33`; `api/narrative.js:20` requires `../lib/unlimited-usage`). No Vercel function calls it, and `captureException` has zero callers. A week of 500s produced no alert. Verified.

## 3. Security and API layer

The API layer has a uniform and correct authentication pattern (Supabase JWT via `auth.getUser()`, actor never taken from the body), a fail-closed timing-safe cron gate, a properly verified and idempotent Stripe webhook, and thorough input bounds on the chat path. The defects below are almost all *authorization* and *ledger* defects, which is consistent with the OWASP Top 10 (2021) finding that Broken Access Control is the most prevalent web application weakness, present in 94% of applications tested.

### Critical
- **C1 — Negative credit consumption** (`api/credits.js:37-46`). Described in §2.1. The ledger row records `amount: 1000`, so the exploit also looks like a legitimate grant.
- **C2 — Cross-tenant "reviewed" stamp** (`api/peer-review.ts:264-272`, `api/peer-review-respond.ts:236-256`). Described in §2.3. The existing `peer-review-lifecycle.test.ts` mocks Supabase and cannot detect a missing filter.

### High
- **H1 — `/api/narrative` is an open Claude proxy.** `system` and `payload` are taken from the request body and passed verbatim (`api/narrative.js:188-196`); no size cap short of Vercel's body limit; 100 calls/day per user. The banned-language scan on this route is explicitly non-blocking. *Fix: server-owned system prompt, ~60 KB payload cap.*
- **H2 — Rate limits defeated by the CHECK constraint** (§2.5). Also `photo-analyze.js` inserts with no `generation_type`, so photos land as `'narrative'` and share the narrative budget.
- **H3 — Credits never gate anything server-side.** No AI or render handler reads `credits_remaining`; deduction is a separate client-initiated POST (`MobileApp.jsx:1296`, `AuthContext.jsx:63`). A client that omits it gets every deliverable free. *Fix: debit inside the handler that produces the deliverable, refund on upstream failure.*
- **H4 — Container path cannot boot** (§2.10). Additionally `server/index.js:18` `require('../lib/sentry')` targets a `.ts` file (always throws under plain Node, swallowed), `tsx` is pruned by `npm ci --omit=dev`, and only 8 of 35 handlers are mounted. `docs/CONTAINER.md` describes a path that does not exist.
- **H5 — Stripe lifecycle gaps.** Only `checkout.session.completed`, `subscription.updated` and `subscription.deleted` are handled; `invoice.paid` is ignored, and `cron-monthly-credit-grant.ts:10-11` says monthly replenishment "happens via the webhook". A Solo-monthly subscriber receives credits once. Portal plan switches (`customer-portal.ts:131-134`) change the Stripe price but never `plan`, `billing_period` or credits. `subscription.deleted` hard-sets `credits_remaining: 1` with no ledger row. Raw Stripe statuses overwrite an admin `suspended` flag.
- **H6 — Unauthenticated checkout with open redirect** (§2.4).
- **H7 — Check-then-act rate limiting** on every AI endpoint (e.g. `field-assistant.ts:1283` vs `:1471`). N parallel requests all pass; failed upstream calls are never counted. With `MAX_OUTPUT_TOKENS = 8000` × 4 tool rounds × retry, a burst is expensive.

### Medium
- Rate-limit cross-talk: `narrative.js:51-58` and `photo-analyze.js:386-393` count all generation types.
- `conversation_id` trusted without ownership check (`field-assistant.ts:326-332`); rows land in another user's conversation.
- Admin endpoint: shared static secret, untyped `amount` (`"abc"` → `NaN` written to `credits_remaining`), no status allow-list, dumps every user's email and Stripe id.
- GDPR erasure incomplete: `audit_log` keeps `actor_email` and IP forever; `marketing_agent_leads` untouched; storage prefixes (`report-templates/{uid}/`, `peer-review-attachments/{uid}/`) orphaned; `invitations.invited_by` has no `ON DELETE`, so `auth.admin.deleteUser` fails for anyone who ever sent an invite. `field-assistant.ts:1053` claims to scrub PII from chat content but `scrubPii` only redacts by key name, so content is stored verbatim. (GDPR Art. 17 requires erasure "without undue delay"; a handler that fails or retains PII is non-compliant regardless of intent.)
- Raw Postgres/Anthropic error text returned to clients in ~15 places (`sites.ts`, `peer-review.ts`, `field-assistant.ts`, `checkout.js`, `narrative.js`, …).
- Spoofable `x-forwarded-for` in the container (no `trust proxy`); unauthenticated endpoints fail open on DB error.
- Inline-AI rewrites bypass the banned-language scan and land in observation fields the PDF path deliberately does not scan.
- Client `context` is serialised into the **system** prompt (`field-assistant.ts:363-372`), and attached documents enter tool results with no data-framing; chat enforcement defaults to `observe`.
- Non-atomic select→compute→update credit arithmetic in five places; `balance_after` can diverge from `credits_remaining`.
- Peer-review magic token travels in query strings (logs, Referer); no rate limit on the public respond endpoint.
- DOCX template parse/render has no per-user rate limit (zip-bomb CPU exposure). Expression injection is *not* possible: docxtemplater is configured with the default property-lookup parser.

### Endpoint coverage
30 routes. Untested handlers: `admin.js`, `audit.js`, `early-access.js`, `reset-credits.js`, `profile/mark-onboarded.ts`, and the five `cron-*.ts` HTTP wrappers (the underlying scripts are tested; the auth-gated wrappers that actually failed 96 times are not). `reset-credits.js` is the only monthly reset and is **not scheduled** in `vercel.json`.

## 4. Database and sync layer

Row-level security is enabled on every table and `auth.uid()` is used correctly everywhere; the `assessments` policy set (migration 014) is the model to copy, and the knowledge-graph and webhook-idempotency migrations are genuinely careful. The defects are scope and process, not RLS syntax.

### Critical
- **C1 — Column-unrestricted profiles UPDATE** (§2.2).
- **C2 — Sync queue overwrite** (§2.6). Compounded by `auth.getUser()` returning no user on an expired refresh token → the upsert is skipped with no queue entry at all (`supabaseStorage.js:498`).

### High
- **H1 — `schema_migrations` has RLS off and is PostgREST-exposed** (`scripts/db-migrate.mjs:51-57`). Migration 026's own comment says the linter flagged it, i.e. someone enabled RLS by hand in production and never committed it. Any anon-key caller can delete or forge ledger rows.
- **H2 — The runner cannot build a fresh database.** `002` alters `profiles`, which only the un-ledgered `supabase/schema.sql` creates; and `schema.sql` creates `assessments` with `id uuid` while `014` (`create table if not exists`) expects `text`. Staging, Supabase branches and disaster recovery are unreachable via `npm run db:migrate`.
- **H3 — First finalize loses the `payload` column and leaves a phantom draft.** `MobileApp.jsx:1681` deletes the draft locally only; the cloud draft keeps the `assessment_uid`; the new `rpt-` row hits the 032 unique index; the retry at `supabaseStorage.js:548-561` drops `payload` and `assessment_uid` on *any* error, not just "undefined column". The finalized report syncs via flattened legacy columns and loses equipment, floor plan, sensor and lab data.
- **H4 — Erasure gaps** (see §3 Medium).
- **H5 — Last-write-wins with no version check** across devices; an offline snapshot overwrites a newer cloud row on reconnect.
- **H6 — Sync can wedge permanently.** `inFlight: true` is persisted to localStorage before a drain; a killed tab leaves it set forever. The queue stores uncompacted base64 photos, appends one entry per autosave with no dedupe, and ignores `STO.set === false` under quota.

### Medium
- `org_members` policies are self-referential (`003:38-47`) → `infinite recursion detected in policy` (42P17) for `organizations`, `org_members`, `invitations`. Latent because the tables are unused.
- Anonymous unbounded inserts into `analytics_events` (`user_id IS NULL` allowed; client never sets it, so the erasure purge matches nothing).
- Users can forge `credits_ledger` rows (`002:33-35`).
- Issued reports are mutable in place; `updated_at` is used as the report date on cloud restore (`fromCloudRow:110,135`). CLAUDE.md: "an issued report's record is the only evidence of what it said."
- `composite` jsonb now holds two incompatible shapes (pre-/post-v3.0) with no discriminator.
- Migration `012` is not idempotent; nine migrations use `create policy` without a guard; `--baseline` is a one-click foot-gun exposed in the CI dropdown; duplicate version numbers are silently dropped.
- No retention policy anywhere; `audit_log` and `analytics_events` grow forever with IP and email.
- `ssl: { rejectUnauthorized: false }` for the production DB in CI.
- Global text PK minted from `Date.now()`; every login pulls every assessment with inline photos via `select('*')` (PostgREST's 1,000-row default will silently truncate).
- Storage buckets have no size or MIME limits.

## 5. Assessment engine and standards corpus

The criteria registry (`src/constants/criteria.js`) is the strongest part of the codebase: every applied threshold carries an averaging period, class, source and severity cap, and the double-entry reconciliation, provenance, coverage and editorial-parity tests are real guards. The CO, formaldehyde, PM2.5/PM10, radon, CO₂-attribution and ASHRAE 55 temperature figures in the registry are correct against the cited editions. The problems are in the surfaces that **bypass** the registry: building profiles, the print/intake surfaces, the Jasper knowledge base, and the report model's own outcome ladder.

### Critical (reaches a client deliverable with a wrong number or attribution)
- **C1/C2/C4 — RH band misattributed** (§2.8), on nine profiles, the DOCX narrative and the Logger card.
- **C3 — Visible-mold findings misstate IICRC S520 and mis-cite NYC to EPA** (`scoring.js:259-263`, `scoring-legacy.js:392-397`, `escalation.js:12-18`). The text says "Moderate visible mold — IICRC S520 Condition 2 likely … EPA Level II (10–30 sq ft)". Under S520 (2015, reaffirmed 2024), *any* actual growth is **Condition 3**; Condition 2 is settled spores without growth; area does not lower the Condition. The Level I–IV square-footage ladder is from the **NYC Department of Health** *Guidelines on Assessment and Remediation of Fungi in Indoor Environments* (2008), not EPA; EPA's *Mold Remediation in Schools and Commercial Buildings* (2008) uses <10 / 10–100 / >100 ft². The intake option says "10–100 sq ft" while the finding prints "10–30". The mold module's own `remediationCondition.js:95` gets this right, so the two engines disagree.
- **C5 — Stale EPA RfC on the Logger card** (`sensorThresholds.js:132`: "~8 ppb"; the registry holds the 2024 final IRIS value, 0.0057 ppm ≈ 7 µg/m³).
- **C6 — Jasper's `exposure_limits` table (returned "verbatim") and Appendix D prose carry wrong durations and attributions:** NIOSH RELs labelled "8-hour" (NIOSH RELs are up-to-10-hour TWAs, per the NIOSH Pocket Guide; the registry itself says `hour10`); ACGIH formaldehyde given as "0.1 ppm Ceiling, A2" (ACGIH revised it in 2017 to TLV-TWA 0.1 ppm / STEL 0.3 ppm, A1); "NIOSH Action Level 0.5 ppm … 29 CFR 1910.1048" (that is OSHA's action level); Δ700 ppm attributed to "62.1-2025 §6" (it is from a since-removed informative appendix, as `criteria.js:575` correctly states).
- **C7 — Healthcare and specialty ACH figures in `buildingProfiles.js` do not match the cited sources.** Procedure room 6 ACH cited to ASHRAE 170-2021 Table 7.1 (170 lists procedure rooms at 15 total ACH); pharmacy 12 ACH "(ISO 7)" (170: 4 ACH general pharmacy; USP <797> ISO 7 buffer rooms: 30 ACH); waiting 4 ACH (170: 12, negative, for ED/radiology waiting); "isolation (protective environment)" required to be negative (PE rooms are positive, AII rooms negative); office 4 ACH cited to ASHRAE 62.1 (62.1 states no ACH); enclosed-parking CO 25 ppm cited to 62.1 (62.1 gives 0.75 cfm/ft²; 25 ppm is IMC §404.1 / ACGIH); warehouse CO > 5 ppm rated **high** citing OSHA (no OSHA figure is 5 ppm); classroom CO₂ > 800 rated **high** citing "EPA TfS" (no such criterion). None of these carry a criterion id, so `criterion-coverage.test.ts` cannot see them. Several figures are marked *verify* rather than asserted; all of them need a primary-source check before the next client report.
- **C8 — "Mølhave 500" and "ASHRAE 62.1 >1000" survive on intake and print** (`questions.js:305,314`; `PrintReport.jsx:606,835`). The `no-molhave` test's regex only fires when word and number share one ≤900-char literal.

### High (changes a conclusion)
- **H1 — Non-numeric readings score as pass** (§2.7, reproduced).
- **H2 — Grab readings still compared to 8-hour PELs outside the registry** (`scoring.js:264-268` "exceeds OSHA PELs", critical; `scoring-legacy.js evalOSHA`; `liveAdvisor.js:111-116, 167-172`, which also calls 0.016 ppm the "NIOSH REL ceiling" — the ceiling is 0.1 ppm). This is the category error CRITERIA.md says was fixed.
- **H3 — `reportModel.paramOutcome` is a second, disagreeing verdict ladder** (`reportModel.js:66-82`): always uses the summer temperature band; CO "acceptable" below 9 while the engine flags ≥ 6; `>=` where the engine uses `>` at every boundary; RH beyond 70/20 rated high while the engine caps at medium. This is exactly what the lost cross-layer consistency test would catch.
- **H4 — CO₂ is never evaluated when airflow was measured** (`scoring.js:104-116`): 3,000 ppm with any `cfm_person` yields an info-only finding. Line 134's "no outdoor baseline" tier is unreachable.
- **H5 — Season fallback on the re-score path.** Only `MobileApp.jsx:1591` passes `assessmentDate`; `AssessmentContext.jsx:85` and `bridge/meta.ts:136` fall back to today; `sensorThresholds.js:31` uses a third rule. Same input, different band by render month.
- **H7 — Drywall moisture flags on any reading ≥ 1** on a 0–100 relative meter (`moldStandards.js:160`, `moistureIndicators.js:268`).

### Medium
- Calibration validity stated as **270 days** in `standards-corpus.js:162,327` and the Jasper KB (`:482`) while the platform enforces 365 and CLAUDE.md says so; the corpus also claims instruments past the window "cannot generate signed deliverables", which is untrue (export is ungated).
- Appendix A of the surviving DOCX is an unguarded standards register (`reportModel.js:160-166, 510`): always appends 62.1/55/NAAQS/OSHA even when unmeasured, and turns every finding `std` string into a row with boilerplate "Referenced in screening interpretation." No golden DOCX fixture exists; `atmosflow-report.test.ts` checks six substrings.
- Jasper prompt constants carry their own threshold copies (`field-assistant-corpus.js:62-63` prints 1000/1500 under an "ASHRAE 62.1-2025" heading — the nesting-inherits-citation trap CLAUDE.md names).
- Recommendations stating unobserved facts: "Deploy portable HEPA units" on any symptom cluster (`scoring-legacy.js:262`); pressurization remediation triggered by the word "negative" in pharmacy context text.
- "hazardous compounding" ships in a profile finding (`buildingProfiles.js:50`) around the banned-term scanner, which does not run on the AtmosFlow DOCX path.
- Boundary conventions differ by layer (`>` vs `>=`); meeting the ASHRAE 62.1 minimum exactly is rated a medium finding.
- Two wood-moisture thresholds (19% in `sampling.js`, 16% in `moldStandards.js`); gypsum and in-slab RH figures attributed to EPA 2008, which states neither.

### Test quality
289 assertions across the engine suites are bare `toBeDefined` / `toBeTruthy` / `not.toThrow`. `src/__tests__/edge-cases.test.js:60-92` asserts only that `'abc'`, `''`, negatives and huge values do not crash, never what severity results — which is how H1 shipped. Modules with no dedicated test: `pressurizationNarrative.js`, `riskBands.js`, `scoring-legacy.js` (`evalOSHA`, `calcVent`, `evalMold`, `detectSBSPattern`), `bridge/meta.ts`, `report/synthesis.ts`.

## 6. Frontend, PWA and delivery

### Structure
`MobileApp.jsx` is 5,461 lines with 79 `useState`, 26 distinct views behind 38 `view === 'x'` branches, 526 inline style objects, zero `React.memo`, and is touched by 36% of all commits (53 of 148). Code churn concentrated in one file is one of the best-established predictors of defect density in the empirical software-engineering literature (Nagappan & Ball, ICSE 2005). Three components are defined *inside* render functions (`TrashView` at `:3492`, `Radio` at `:312`, `Row` at `:4375`), so each parent re-render remounts them; a 30-second `setClock` interval (`:935`) re-renders the whole shell while idle, which resets the Trash screen every 30 s.

### Performance
No `React.lazy` on the production path. `DocxReport`, `PrintReport`, `FieldAssistant`, `AdminDashboard`, `SensorDataPage` (recharts), and the CoC forms (jspdf) are statically imported by `MobileApp`, which is why the main chunk is 3.1 MB / 930 KB gzip. The HTTP Archive Web Almanac reports median mobile JavaScript transfer at roughly 550–600 KB; this PWA aimed at field phones ships about 1.6× that before first paint, and every deploy invalidates one chunk. `@mui/material`, `@mui/x-date-pickers`, `@emotion/*`, `vaul` and `@testing-library/jest-dom` are declared and have **zero** imports; `html2canvas` and `esbuild` are imported and **not** declared. `@types/react` is pinned to 19 while `react` is 18.

### Navigation and state
Routing is in-memory (`useState('projects')`) with no `pushState`/`popstate`; Android back and iOS swipe-back exit the PWA, refresh loses position, and nothing is deep-linkable. `AssessmentContext` packs zones, base64 photos, recs and narrative into one memo value, so every keystroke re-renders every consumer. `useBleInstrument.js:57-62` has a stale-closure cleanup: the unmount effect captures the first-render `cleanup` where `device` is null, so GATT is never disconnected on unmount. Photos are 400 px base64 JPEGs held in React state and localStorage; `storage.js:26` returns `false` on quota with no user feedback.

### Service worker
`/api/*` is correctly never cached, caches are versioned, and the precache manifest plugin is well done. Two risks: `sw.js:169` applies stale-while-revalidate to *any* other same-origin GET (allow-by-default; a future authenticated non-`/api` route would be cached on shared devices), and `skipWaiting` + `clients.claim` with no `controllerchange` listener means a tab can run old JS against a new cache mid-session.

### Accessibility
`index.html:16` sets `user-scalable=no` (WCAG 2.1 SC 1.4.4 failure). `index.html:124,149` document contrast ratios of ~1.9:1 and ~2.6:1 against the 4.5:1 AA minimum (SC 1.4.3). 1 `htmlFor` for 30 labels; 18 `alt` for 23 images; 36 `outline:'none'` against 8 `focus-visible` rules; 13 of 17 clickable `<div>`s lack role/tabIndex/keyboard handling; the bottom sheet has `aria-modal` but no focus trap. `TEXT_SECONDARY = '#A8B0BD'` is a hard-coded dark-theme hex used in 17 places.

### Quality gates and process
- **No CI** (§2.9). Hilton et al. (ASE 2016) found projects using CI release more than twice as often and catch integration failures earlier; the specific incident in this repo's CHANGELOG is the textbook case.
- **85% of production code has no static analysis** (table in §1). `eslint.config.mjs` has no `rules` block, so "lint passes" means "files parse". Gao, Bird & Barr (ICSE 2017) found that a static type system would have detected about 15% of public JavaScript bugs at commit time; `strict: false` with `src/` excluded forgoes that entirely, and the react-hooks plugin is not installed, so the ten `exhaustive-deps` disables are cosmetic.
- **The acceptance gates are 85% grep.** `prod-ready.json`: 75 criteria, 408 checks, of which 214 `grep_matches`, 154 `file_exists`, 27 `grep_excludes`, 11 `npm_script` — and 8 of the 11 are the same full `test` run. The runner supports `rendered_*` check types that no config uses.
